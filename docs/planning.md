## 개요

이음길 AI는 휠체어 이용자, 보행이 불편한 고령자, 유모차 동반 가족이 영동권(강릉·속초·동해) 관광지를 당일부터 2박 3일까지의 루트로 돌 수 있는지 판단하는 웹서비스다. 한국관광공사 무장애 여행정보(문장으로만 된 공공데이터)를 LLM이 읽고, 이 사람 기준으로 판단하고, 성격이 다른 일정 2\~3안으로 엮고, 현장에서 쓸 말(도착 후 동선, 출발 전 확인할 질문 + 공식 전화번호)로 풀어 준다.

- **과제명 후보**: 이음길 AI: 관광약자를 위한 조건 검증형 영동권 여행 루트 플래너
- **목표 시점**: **12월 7일까지 GitHub 제출**. 평가는 GitHub 저장소만 보고 초기 계획서 대비 완성도를 본다(중간평가 없음, 부총리상 추천 후보 12팀 대상). 12월 중 성과공유회.
- **핵심 원칙**: LLM이 읽고·판단하고·계획하고·풀어준다. 코드는 계산과 검사만 강제한다. '모름'은 숨기지 않고 질문과 공식 전화번호로 확인할 방법을 준다. (11월 10일 개정, 상세는 `docs/ai-plan.md` v3)

## 사용자 유형과 필수 조건

세 유형은 막히는 지점이 달라서 유형마다 필수 조건 세트를 따로 적용한다. 여러 유형을 고르면 각 항목에서 가장 엄격한 값을 쓴다. 예를 들어 고령자 + 유모차를 고르면 걸을 수 있는 거리와 수유실을 모두 본다.

| 항목 | 휠체어 | 유모차 | 보행 불편 고령자 |
| --- | --- | --- | --- |
| 계단·단차 없는 진입로 | 필수 | 주의 표시(짧은 단차는 들어서 통과) | 주의 표시(손잡이 있으면 가능) |
| 엘리베이터(층이 있는 시설) | 필수 | 필수 | 선호 |
| 경사로 기울기 | 필수(급경사 불가) | 선호 | 주의 표시(긴 오르막) |
| 노면(모래·자갈·흙길) | 필수(포장·덱크 구간 있어야 함) | 선호 | 주의 표시(넘어짐 위험) |
| 장애인 화장실 | 필수 | — | 선호 |
| 기저귀 교환대·수유실 | — | 선호 | — |
| 장애인 전용 주차구역 | 필수(자가용 + 표지 차량일 때) | 이용 대상 아님 | 장애 등록 시만(입력 선택) |
| 주차장에서 입구까지 거리 | 주의 표시 | 주의 표시 | 필수(입력한 거리 이하) |
| 관람 동선 길이 | — | 선호 | 필수(입력한 거리 이하) |
| 휴식 공간(벤치·쉬터) | — | 선호 | 선호 |
| 휠체어·유모차 대여 | 선호 | 선호 | 선호 |

- **필수**: 하나라도 어기면 후보에서 빠지고 '불가 + 대안' 목록으로 간다.
- **선호**: 추천 점수에만 더해진다.
- **주의 표시**: 일정에는 남기고 장소 카드에 경고 문구를 붙인다.
- **고령자 입력값**: 한 번에 걸을 수 있는 거리(100m / 300m / 500m / 제한 없음). 주차장→입구, 관람 동선과 비교한다.
- 사용자는 유형을 고른 뒤 자동으로 켜진 조건을 하나씩 끄거나 더할 수 있다.

## 사용자 흐름과 화면

입력은 설문조사처럼 4단계로 나누고, 한 화면에는 질문 하나만 둔다. 결과 화면은 지도와 루트를 함께 보여준다.

**시작 화면**: 서비스 한 줄 소개, '시작하기', '예시 루트 바로 보기'. 예시 루트는 저장소에 미리 만들어 둔 일정 파일이라 심사위원이 입력 없이(LLM 호출 없이) 결과를 볼 수 있다(개발 예정).
처음 들어오면 로고와 한 줄 소개를 약 1.2초 보여주고 자동으로 넘어간다(탭마다 한 번, 누르면 건너뜀, 움직임 줄이기 설정이면 생략).
글자 크기는 rem 단위라 휴대폰·브라우저의 글자 크기 설정과 확대를 그대로 따른다('가 글씨 크게' 버튼은 11/11 실사용 피드백으로 뺐다).

**입력 4단계**

1. **언제, 어디서**: 달력에서 가는 날·오는 날(당일\~2박 3일). 영동 도착 지점, 이동수단(자가용·렌터카 / 택시), 자가용이면 장애인 표지 차량 여부. 첫날 시작 시각, 마지막 날 마치는 시각과 떠나는 곳(기본값: 도착 지점). 1박 이상이면 숙소 지역(강릉·속초·동해·미정). 2박 3일은 밤마다 고른다(둘째 밤 줄이 하나 더, 기본 '첫째 밤과 같음'). 숙소를 옮기면 2일째는 첫째 밤 숙소에서 출발해 둘째 밤 숙소에서 끝나고, 그날 후보는 출발·도착 양쪽 근처에서 고른다.
2. **누구와**: 휠체어 / 보행 불편 고령자 / 유모차, 중복 선택.
3. **꼭 필요한 조건**: 유형별 필수 조건이 미리 켜져 있고 끄거나 더할 수 있다. 장애인 전용 주차는 1단계에서 표지 차량을 고른 경우에만 나온다. 고령자를 고르면 한 번에 걸을 수 있는 거리를 고른다.
4. **좋아하는 곳**: 바다·해변 / 자연·산책 / 역사·문화 / 전시·박물관 / 시장·먹거리 / 전망·체험 중 복수 선택. 일정 밀도(여유롭게 / 보통 / 많이). 꼭 가고 싶은 곳 검색(선택). 입력 화면에 "이름·연락처는 받지 않고, 고른 조건은 일정 계산에만 써요"를 표시한다.

**만드는 중 화면**: 진행률(%)과 단계(조건에 맞는 장소 고르기 → AI 장소 판단 → AI 일정 짜기 → 일정 점검), AI가 살펴보는 장소 이름, 진행 기록(예: "장소 판단 2/3번째 끝", "A안 검사 통과 · 4곳", "B안: 운영시간을 넘는 곳이 있어 고치는 중")을 서버 스트림 그대로 보여준다. 몇 초 지났는지만 보여주면 실제로 진행 중인지 알 수 없다는 시연 피드백(11/10)을 반영했다.

**결과 화면 구성** (상세: `docs/ai-plan.md` 화면 표. '안 비교'는 시안에 없어 새로 그렸다)

- **안 비교**: 성격이 다른 일정 2\~3안(예: 여유롭게 / 바다 중심 / 비 와도 괜찮게)을 카드로 위아래에 쌓아 보여준다. 제목, 갈 곳 한 줄 요약(예: "강릉 · 오죽헌 → 선교장 → 허난설헌 생가터 외 1곳"), 장소 수, 이동 시간 합계, 전화로 확인할 곳 수. 안을 누르면 그 안의 상세 일정으로 자동으로 내려간다. 후보가 적으면 1안만 보여주고 그렇다고 알린다. **2박 3일은 1안**(11/14): 고른 밀도 + 좋아하는 곳 중심으로 하루하루 꼼꼼하게 짜고, 장소마다 [바꾸기]로 고친다(이유를 결과 위에 안내).
- **날짜별 탭**: 고른 안을 일차별 탭으로 본다. 탭마다 판정, 지도, 루트가 바뀐다.
- **판정 배지**: "약 5\~6시간 · 여유 있어요"처럼 여유 / 빠듯 / 부족 중 하나(코드 계산).
- **지도**: 방문 순서 번호 + 짧은 장소 이름, 자동차 경로선(흰 테두리, 구간마다 진행 방향 화살표와 이동시간), 출발·도착 표(경로선을 가리지 않게 위로 띄움). 번호를 누르면 사진·시각·판단 카드와 [일정에서 보기], 일정 카드의 번호를 누르면 지도가 그 장소로(11/14). "휠체어 안전 경로가 아닌 일반 차량 경로" 안내를 붙인다. 안 비교 화면과 확정 일정 페이지에 같은 부품을 쓴다. 안 비교 화면에서는 고른 안·날짜를 바꾸면 지도도 함께 바뀐다.
- **장소 카드**: 처음에는 핵심만 — 관광지 사진(누르면 크게 보기, 사진마다 출처·편의시설 표시), 도착 예상 시각(코드 계산), 이름, 판단 칩(적합 / 주의 / 확인 필요) + 확신도, 한 줄 이유, 공식 전화 버튼, [바꾸기], [자세히]. [자세히]를 누르면 AI 판단 이유, 도착하면(동선), 출발 전 확인(질문), 근거(관광공사 무장애 정보 항목, AI 정리)가 펼쳐진다. 글이 많아 읽기 어렵다는 시연 피드백(11/10)을 반영했다.
- **구간 이동**: 카드 사이에 "차량 약 25분 · 14km".
- **점심·휴식 블록**: 일정이 12\~14시에 걸리면 60분 빈 블록. 음식점은 추천하지 않는다.
- **어려운 곳과 대안**: 취향에 맞지만 부적합인 곳을 이유와 함께 보여주고, 근처 적합 장소를 코드가 골라 LLM이 이유를 붙인다.
- **AI 설계 과정 보기(접힘)**: 판단 결과 요약, 검사에서 고친 내역, 평가 점수.
- **장소 바꾸기**: [바꾸기]를 누르면 근처 후보(최대 3곳: 이름, 판단, 거리, AI 판단 이유)가 나온다. 고르면 그날 시각을 다시 계산하고, 바꾼 카드에 '바꾼 장소 · 원래 ○○'를 붙인다. 원래 장소로 되돌릴 수 있다.
- **이 일정으로 정하기**: 출발 전 확인할 것(장소별 질문 + 전화) 모음을 띄우고, '확정 일정 지도로 보기'로 확정 일정 페이지에 간다.
- **확정 일정 페이지**(`/trip/[id]/final`): 정한 안 하나만, 날짜 탭, 지도(번호 + 일반 차량 경로선), 시간순 목록(시각·이름·판단·전화), 출발 전 확인할 것. 모바일은 위 지도 + 아래 목록, PC는 왼쪽 지도 + 오른쪽 목록. 지도를 못 띄우면 안내 문구만, 경로를 못 받으면 점선 직선.
- **공유(나중에)**: 링크 복사, 일차별 요약 이미지 저장.
- **오류 화면**: 경로를 못 불러옴(직선거리 추정치로 대체), 조건에 맞는 곳 없음(완화 제안), AI 실패(규칙 일정 1안 + "AI 설계를 불러오지 못했어요").

**화면 배치**: 창 너비에 따라 바로 바뀐다(11/11). 휴대폰(768px 미만)은 한 칸, 태블릿(768px~)은 넓은 한 칸, PC(1024px~)는 두 칸, 넓은 PC(1280px~)의 안 비교는 안 고르기 · 상세 · 지도 3칸. 시작 화면은 PC에서 왼쪽 소개 + 오른쪽 실제 결과 화면 미리보기, 입력 4단계는 가운데 질문 + 오른쪽 '고른 조건' 요약, 확정 일정은 왼쪽 지도 + 오른쪽 루트. 바꾸기·확정 창은 휴대폰에서 아래에서 올라오고 PC에서는 가운데 대화창. (나중에) 공유 링크로 열면 편집 버튼 대신 "내 일정으로 복사"를 보여준다.

## 일정 생성 로직

LLM이 읽고·판단하고·계획하고·풀어주며, 코드는 계산과 검사만 강제한다. 출력 형식(JSON 틀), 검증 규칙, 호출 횟수는 `docs/ai-plan.md` v3가 기준이다.

**미리(스크립트)**: ① 읽기 — 152곳의 API 문장(무장애·소개·반복·개요)을 LLM이 읽어 access 10항목 값(가능/부분가능/불가/모름) + 메모 + 근거 + '모름'이면 질문, 운영시간(`open/close/last_entry`, 휴무), 도착 후 동선 초안을 만든다. 사람이 확인한 값이 생기면 등급 `human`으로 덮어쓴다(선택).

**요청할 때(`POST /api/plan`, 진행 상황 스트리밍)**

1. **후보 거르기(코드)**: 지역 밖, 그 날 휴무, 필수 조건이 '불가'인 곳을 뺀다. 최대 20곳.
2. **② 판단(LLM)**: 후보를 한 호출에 묶어 3번 판단한다. 적합 / 주의 / 부적합 / 확인 필요 + 이유 + 근거 + 확신도. 안전 하한(코드): 필수 '불가' → 부적합, '부분가능' → 최소 주의, 휠체어 진입 원문 없음 → 확인 필요. 그 밖의 '모름'은 질문으로 붙인다(11/10 개정).
3. **이동시간 표**: AI에게 주는 장소 사이 이동시간 표는 직선거리 어림(후보 20~30곳을 모두 카카오로 짝지으면 호출이 너무 많다). **다 짠 안은 날짜마다 카카오 다중 경유지 길찾기 1회로 실제 구간 시간을 받아 다시 검사하고, 넘치면 코드가 시간을 맞춘다**(11/14). 카카오 값은 이 검사에만 쓰고 버리며, 결과·확정 화면은 열 때마다 `/api/legs`로 다시 받아 시각을 계산한다(못 받은 구간만 '추정').
4. **③ 계획(LLM)**: 후보는 적합·주의를 먼저, 모자라면 확인 필요로 채운다(표시해서). 한 호출로 방향이 다른 2\~3안. 장소·순서·날짜·체류·쉬는 곳·이유·주의·확인 질문. 시각은 쓰지 않는다.
5. **시각 계산 + 검사(코드)**: 이동 + 체류 + 유형별 여유 + 승하차 여유 + 12\~14시 점심 60분으로 시각을 계산하고 운영시간·하루 범위·체류 범위를 검사한다.
6. **수정·평가**: 걸린 안만 위반 내용을 돌려줘 다시 받는다(최대 2회). 평가자 LLM이 피로도·여유·취향·화장실 간격을 1\~5점으로 보고, 2점 이하면 1회 수정. 안끼리 장소가 절반 넘게 겹치면 다시 만든다. 끝까지 못 통과한 안은 뺀다.
7. **④ 풀어주기**: 도착 후 동선은 ① 읽기에서 정리한 값, 출발 전 확인할 것(질문 + 공식 전화번호)은 확정 화면 체크리스트로 보여준다. 요청할 때 AI로 한 번 더 다듬는 호출은 11/14에 뺐다(도착 후 동선은 ① 읽기에서 장소마다 이미 정리해 카드에 보여 주고, 출발 전 확인할 것(질문 + 공식 전화)은 체크리스트로 제공한다. 요청할 때 한 번 더 다듬는 AI 호출은 시간만 늘어 하지 않기로 함). 장소 바꾸기 후보는 이미 코드가 고르고 ② 판단 이유를 그대로 쓴다(11/10 2차).
8. **실패 시 규칙 일정**: LLM이 실패하면 아래 '규칙 일정'으로 1안을 만든다.
9. **경로선**: 확정 일정 페이지를 열 때 날짜마다 '다중 경유지 길찾기'를 1회 호출한다(`/api/route-line`, 저장 안 함).

LLM 호출은 요청당 약 5\~8회(판단 3, 계획 1, 수정 0\~2, 평가 1\~2)이고, 카카오 길찾기는 하루치 일정마다 최대 7회다.

### 규칙 일정 (LLM 실패 시 대체 경로)

LLM 없이도 시연이 멈추지 않도록 아래 규칙 일정은 그대로 유지한다. 개수·배분·시간 규칙은 AI 일정의 검사 기준으로도 쓴다.

1. **후보 걸러내기**: 영동권 전체 장소에서 선택한 유형의 필수 조건을 어기는 곳, 그 날 휴무인 곳을 뺀다. 장애인 전용 주차 조건은 자가용 + 장애인 표지 차량일 때만 켠다. 빠진 곳 중 취향에 맞는 곳은 '불가 + 대안' 목록으로 보낸다.
2. **점수 매기기**: 취향 일치 + 선호 조건 충족 개수 + 도착 지점과의 거리. 꼭 가고 싶은 곳은 항상 포함한다.
3. **개수 정하기**: 반나절 2\~3곳, 하루 3\~5곳. 일정 밀도(여유롭게 / 보통 / 많이)가 하한·중간·상한을 고른다. 여러 날이면 날마다 같은 규칙을 적용하고, 조건을 통과한 장소가 모자라면 상한을 자동으로 낮추고 안내한다.
4. **날짜별 배분(1박 이상)**: 장소를 지역(강릉·속초·동해) 단위로 묶어 날짜에 나눈다. 첫날은 도착 지점 쪽, 다음 날부터는 숙소 지역 쪽 묶음부터 채운다. 같은 장소는 한 번만 들어간다. 중간 날은 숙소 09:30 출발 \~ 18:00 도착을 기본값으로 두고, 마지막 날은 떠나는 곳(기본값: 도착 지점)에서 끝난다. 숙소가 '미정'이면 첫날 마지막 장소 근처를 숙소로 가정하고 그렇게 표시한다.
5. **이동시간 표 받기**: 점수 상위 장소와 도착 지점 사이의 차량 이동시간을 카카오 '다중 목적지 길찾기'로 받는다(날짜마다, 출발점마다 1회, 최대 6회).
6. **순서 정하기**: 장소가 5곳 이하라 가능한 순서를 모두(최대 120가지) 계산한다. 비용 = 총 이동시간 + 운영시간 위반 벌점. 가장 낮은 순서를 고른다.
7. **시간 범위 계산**: 총 이동시간 + 장소별 권장 체류 범위의 합 + 유형별 여유시간. 여유시간은 휠체어·고령자 선택 시 체류 범위에 20\~30%를 더하는 것을 초기값으로 두고 조정한다. 여기에 휠체어를 고르면 장소마다 승하차 여유시간을, 일정이 12\~14시에 걸리면 점심·휴식 60분 블록을 더한다. 승하차 여유시간 값은 조사나 테스트로 정한다.
8. **판정**: 범위 최대값 ≤ 여행 시간 → 여유. 최소값 ≤ 여행 시간 < 최대값 → 빠듯. 최소값 > 여행 시간 → 부족(점수가 가장 낮은 1곳을 뺀 안을 함께 제시). 1박 이상이면 날짜마다 따로 판정한다.
9. **운영시간 검사**: 늦은 쪽 도착 예상 시각이 입장 마감을 넘으면 경고하고, 이른 쪽도 넘으면 순서에서 뺀다. 시각 단위가 아니라 휴무일·마감 같은 큰 제약만 보며, 여행 날짜에 맞춰 하절기·동절기 운영시간과 명절 휴무를 고른다.
10. **경로선**: 정해진 순서로 '다중 경유지 길찾기'를 1회 호출해 지도에 그릴 선과 구간별 시간·거리를 받는다.
11. **완화 제안**: 후보가 부족하면 필수 조건을 하나씩 풀어 보고 늘어나는 장소 수를 계산한다. 결과는 LLM이 한 문장으로 설명한다.

장소 바꾸기(그리고 나중에 넣을 빼기·순서 변경·다른 날로 옮기기) 때는 LLM을 다시 부르지 않고, 화면에서 코드가 시각 계산·검사만 다시 돌린다. 경로선은 확정 일정 페이지를 열 때 다시 받는다. 칩([더 여유롭게] 등, 나중에)은 고른 안만 LLM에 다시 요청한다. 카카오는 길찾기 결과를 저장해 두고 다시 쓰는 것을 금지하므로, 공유 링크는 안 JSON(장소·순서·체류·이유)만 저장하고 열 때 이동시간·시각·경로를 다시 계산한다.

## 데이터 구조

장소 데이터는 저장소 안 `data/places.json` 하나로 둔다. 관광공사 API 기본 정보 + ① 읽기 결과(등급 `ai`) + 사람 확인 값(등급 `human`)이 들어가고, 심사위원이 GitHub에서 바로 볼 수 있다. 빌드할 때 형식 검사(JSON Schema)를 돌린다. 장소별 근거 문장은 `data/docs/places/{id}.md`(문단 id + 출처 URL), API 원본은 `data/raw/`(커밋 안 함). Supabase에는 공유된 일정만 저장한다.

| 필드 | 내용 | 예시 |

**access 항목(조건표와 1:1)**: step\_free\_entrance, elevator, slope, surface, accessible\_toilet, diaper\_nursing, disabled\_parking, rest\_area, rental\_wheelchair, rental\_stroller. 값은 `가능 / 부분가능 / 불가 / 모름` 중 하나다. 부분가능은 메모(예: "해변 덱크까지 가능, 모래사장 진입 불가"), 모름은 물어볼 질문(예: "2층 전시실에 엘리베이터로 갈 수 있나요?")이 반드시 있어야 한다.

- 빌드 검사: '모름'에 질문이 없거나, 부분가능에 메모가 없거나, 장소에 전화번호가 없으면 실패한다. 빈칸을 지어내지 않고 확인할 방법을 반드시 붙이기 위해서다.
- 등급: `ai`(LLM이 관광공사 문장을 읽고 정리), `human`(사람이 전화·현장으로 확인). 화면에 함께 표시한다.
- API에 없는 항목(쉴 곳, 주차장→입구 거리, 관람 동선 길이)과 대부분 비어 있는 항목(노면 88%, 경사 56% 모름)은 '모름'으로 시작하고, 사용자에게 질문 + 공식 전화번호로 확인할 방법을 준다(사람 판정은 하지 않음).
- 관광공사 분류가 자연관광·도시공원이면 '층이 없는 야외 시설'로 보고 엘리베이터를 '가능'으로 둔다(코드 규칙, 근거 `class-1`).

  구현(11/12): 1유형은 작게 잘라 `public/photos/`에 저장해 카드에 쓰고, 3유형은 저장하지 않고 원본을 통째로(자르지 않고) 보여 준다. 화장실 같은 편의시설 사진은 대표가 되지 않고, 크게 보기에서 "편의시설 사진"으로 표시해 근거로 보여 준다. 분류 결과는 `data/photos.json`(사진 출처 목록 겸용).

## LLM 활용 설계

**왜 LLM이 메인인가**: 관광공사 무장애 정보는 "출입구까지 경사로가 설치되어 있음(완만함)" 같은 짧은 문장으로만 있어 코드로는 가능/불가를 가를 수 없다. 기존 사이트는 문장을 그대로 보여주고 판단을 여행자에게 넘긴다. 이음길은 LLM이 이 문장을 읽고, 이 사람 기준으로 판단하고, 일정으로 엮고, 현장에서 쓸 말로 풀어준다. LLM을 빼면 152곳 데이터를 판단에 쓸 수 없다. **출력 형식, 검증 규칙, 파일 배치, 작업 순서는 `docs/ai-plan.md` v3가 기준이다.**

| 일 | 언제 | 받는 것 | 내놓는 것(JSON) | 코드가 강제하는 것 |
| --- | --- | --- | --- | --- |
| ① 읽기 | 미리, 152곳(완료) | 장소별 API 문장 | access 값·메모·근거·질문, 운영시간, 동선 초안 | 스키마·근거 id 검사, 반복·모델 간 일치율 |
| ② 판단 | 요청할 때 | ① 결과 + 원문 + 사용자 조건 | 적합 / 주의 / 부적합 / 확인 필요 + 이유 + 근거 + 확신도 | 안전 하한, 3회 비교로 확신도 |
| ③ 계획 | 요청할 때 | 적합·주의 장소 우선 + 확인 필요(표시), 이동시간 표, 운영시간, 화장실 위치 | 성격이 다른 2\~3안(장소·순서·체류·이유·주의·질문) | 시각 계산, 운영시간·하루 범위 검사, 걸린 안만 수정, 통과한 안만 노출 |
| ④ 풀어주기 | 미리 + 요청할 때 | 동선 초안, 판단 이유, 안 | 도착 후 동선, 출발 전 확인할 것, 대안 이유 | 대안 장소는 코드가 고름 |

**원칙**

- **JSON으로만 받는다**: 모든 출력은 스키마(ajv)로 검사한다. 형식 오류면 1회 재시도, 그래도 틀리면 버린다. 화면은 JSON을 받아 카드·지도·타임라인으로 그린다.
- **근거 없는 말 금지**: 넘겨준 문장의 근거 id가 없는 판단·문장은 버린다. 입력에 없는 시설·시간·거리를 쓰지 않는다. 빈칸은 '모름'.
- **시각은 코드가**: LLM은 시각을 쓰지 않는다. 화면의 "10:30 도착"은 전부 코드가 계산한 값이다.
- **안전 하한은 코드가**: 필수 '불가' → 부적합, '부분가능' → 최소 주의, 휠체어 진입 원문 없음 → 확인 필요. 그 밖의 '모름'은 질문 + 전화번호로 붙인다(11/10 개정). LLM은 더 보수적으로만 바꿀 수 있다.
- **개인정보 없음**: Gemini 무료 등급은 보낸 내용이 Google 모델 학습에 쓰일 수 있다. `PlanInput`과 장소 정보만 보내고, 자유 입력이 없어 이름·연락처가 들어갈 경로가 없다.
- **실패해도 동작**: 시간 초과, 형식 오류, 호출 한도면 규칙 일정 1안을 보여준다. 시연이 멈추지 않게 하기 위해서다.
- **검증 기록**: CI는 가짜 LLM으로 가드를 검사한다. `scripts/eval-ai.ts`로 사람 정답 없이 자동으로 잴 수 있는 지표(근거 없이 채운 값 0건(완료), 같은 모델 반복 일치율(① 읽기를 40곳 다시 돌림), 모델 간 일치율(Flash-Lite vs Flash, 40곳), ② 판단 3회 일치율(확신도 분포), 안전 하한 위반 0건(테스트), ③ 규칙 일정 대비 위반 수·평가 점수)를 재서 `docs/eval/`에 남긴다. 정확도가 아니라 **일관성** 지표라는 점을 README·발표에 그대로 밝힌다.
- **제공자 교체 가능**: LLM 호출을 `src/lib/llm.ts` 한 파일로 묶고 모델명은 환경변수로 둔다.

## 기술 스택과 외부 API

Next.js 하나로 화면과 서버 API를 모두 만들고, 서비스가 부르는 외부 서비스는 카카오·Gemini 두 가지다(Supabase는 공유 기능과 함께 나중에). 관광공사 API는 데이터 수집 스크립트에서만 쓴다. 모두 무료 등급 범위다.

| 이동시간·경로 | 카카오모빌리티 다중 목적지 / 1:1 / 다중 경유지 길찾기 | 순서 계산, 경로선 | 비상업 무료 쿼터. 결과 저장·재사용 금지. 도보 길찾기는 유료 제휴 전용이라 쓰지 않음. **다중 목적지는 출발점 반경 10km 안만 계산**(11/10 시험: 강릉역→속초 "반경 범위를 벗어남") → 10km 밖은 1:1 길찾기, 호출이 많으면 직선거리×보정계수 "추정치" |

## GitHub·제출 전략

GitHub Organization을 만들고 그 안에 **공개** 저장소 하나를 두는 것을 추천한다. 제출 링크가 팀 이름으로 나가고, Vercel 무료 플랜은 Organization의 공개 저장소는 배포할 수 있다.

| 선택지 | 제출 링크 모양 | 장점 | 주의할 점 |
| --- | --- | --- | --- |
| Organization + 공개 저장소(추천) | github.com/팀이름/저장소 | 팀 프로젝트로 보임, 팀원 권한 관리, 나중에 저장소를 더 만들기 쉬움 | 저장소를 비공개로 바꾸면 Vercel 무료 배포가 막힘. 배포는 본인 커밋으로만 자동 실행 |
| 개인 계정 저장소 | github.com/kjhmoon/저장소 | 설정이 가장 단순, Vercel 제약 없음 | 개인 프로젝트처럼 보임 |

- **첫날 검증**: Organization에 저장소를 만든 직후 빈 Next.js를 Vercel에 배포해 본다. 막히면 개인 계정으로 옮긴다. GitHub는 저장소를 옮겨도 이전 주소를 새 주소로 연결해 준다.
- **오늘부터 공개**: 커밋 기록이 공고의 '진행률·성실도'를 보여 주는 증거다. 작은 단위로 자주 커밋하고, 커밋 메시지는 한국어로 무엇을 바꿨는지 적는다.
- **README 구성**: 한 줄 소개, 배포 URL, 시연 GIF·영상, 문제 정의, 구조 그림(LLM 4가지 일 + 코드 검사), 사용자 유형별 조건표, 데이터 출처·검수 방법, 실행 방법, 한계와 면책("일반 차량 경로, 현장 상황과 다를 수 있음"), 팀 소개.
- **저장소에 함께 올릴 것**: `data/places.json`과 데이터 사전, 데이터 정리 스크립트, LLM 테스트 시나리오와 결과, 사진 출처 목록.
- **올리지 않을 것**: API 키, `.env` 파일, 출처 표기 조건이 불분명한 사진 원본.

## 역할 분담

개발은 공지혁이 전부 맡고, 강환일은 장소 조사와 주간보고를 맡는다. 신청서의 분담(강환일=백엔드)과 달라진 점은 주간보고에 적는다.

| 담당 | 맡는 일 |
| --- | --- |
| 공지혁 | 기획 확정, 화면·서버·데이터 구조 개발, 외부 API 연동, 배포, README |
| 강환일 | 관광지 후보별 무장애 항목 조사(인터넷·전화), 사진과 출처·공공누리 유형 정리, 주간보고 작성(사진 포함) |
| 공동 | 데이터 최종 검수, 기능 테스트, 발표 자료와 결과보고서 |

주간보고에는 "범위를 강릉에서 영동권(강릉·속초·동해)으로 확대"와 실제 역할을 명시한다. 신청서에도 향후 영동권 확대를 적었으므로 계획과 어긋나지 않는다.

## 위험과 미정 사항

공공데이터 수집으로 '장소가 0곳' 위험은 사라졌다. 이제 큰 위험은 LLM 판단의 정확도와 무료 호출 한도다.

| 위험 | 대응 |
| --- | --- |
| 확인되지 않는 항목이 남음 | '모름'으로 두고 질문 + 공식 전화번호를 붙인다. 적합·주의여도 물어볼 것이 있으면 '전화로 확인할 것 있음'을 칩에 함께 표시한다(11/10) |
| API에 노면·경사·거리가 거의 없어 휠체어·어르신은 대부분 '확인 필요' | 확인 필요 장소도 일정에 넣되 질문 + 전화번호로 분명히 표시(11/10 결정). 사람 판정은 하지 않고(11/10), 사용자가 출발 전에 확인할 수 있게 한다 |
| LLM이 문장을 잘못 읽음(① 읽기 오판) | 근거 없는 값은 코드가 '모름'으로 바꾼다. 반복·모델 간 일치율로 흔들리는 항목을 찾아 프롬프트를 고친다. 화면에 'AI 정리' 등급과 근거 원문을 함께 보여줘 사용자가 직접 확인할 수 있게 한다 |
| 지도 이미지 캐처가 막힘 | 장소 위치·순서를 단순한 그림으로 직접 그려 요약 이미지에 넣는다 |
| 카카오 길찾기 호출 오류·한도 | 직선거리 × 보정계수로 임시 이동시간을 보여주고 "추정치"로 표시한다 |
| Gemini 무료 한도 초과(시연 중) | 규칙 일정 1안으로 대체. ①은 미리 돌려 두고, 판단은 후보 최대 20곳을 한 호출에 묶는다. 필요하면 주간보고 지원요청으로 유료 API를 요청 |
| 공공데이터가 오래되거나 틀림 | 확인일·출처를 카드에 표시하고 '출발 전 확인' 질문 + 전화번호를 늘 붙인다. 관광공사 API는 하루 1번 갱신되므로 제출 전에 다시 받는다 |
| Vercel이 Organization 저장소 배포를 막음 | 개인 계정으로 저장소를 옮긴다 |
| 심사에서 "열린관광 사이트가 있는데?" | 열린관광은 문장을 그대로 보여주고 판단을 여행자에게 넘긴다. 이음길은 같은 공공데이터를 LLM이 이 사람 기준으로 판단해 일정 2\~3안과 현장 안내로 바꾼다는 점을 같은 장소 비교 시연으로 보여준다 |
| 유형별로 조건을 통과한 장소가 모자람(특히 2박 3일) | 조사가 끝나면 유형별 통과 장소 수를 센다. 모자란 조합은 하루 상한을 자동으로 낮추고, 그래도 부족하면 그렇다고 안내한다 |
