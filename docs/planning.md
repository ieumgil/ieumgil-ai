# 이음길 AI 기획·설계 문서

팀 이음길 · 처음 작성 2026년 11월 9일 · 최근 개정 11월 25일 · 날짜별로 바꾼 내용은 맨 아래 [결정 기록](#결정-기록)에 모았다.

## 개요

이음길 AI는 휠체어 이용자, 보행이 불편한 어르신, 유모차를 끄는 가족이 영동권(강릉·속초·동해) 관광지를 당일부터 2박 3일까지 돌 수 있는지 판단해 주는 웹서비스다. 한국관광공사 무장애 여행정보는 문장으로만 된 공공데이터다. 이 문장을 AI(LLM)가 읽고, 함께 가는 사람 기준으로 판단하고, 성격이 다른 일정 2\~3개로 엮는다. 현장에서 쓸 안내(도착한 뒤 동선, 출발 전에 전화로 물어볼 질문과 공식 전화번호)도 함께 붙인다. 정한 일정은 **읽기 전용 공유 링크**와 **A4 한 장 일정표**로 함께 가는 사람과 나누고, 여행 당일에도 휴대폰으로 다시 연다.

- **과제명**: 이음길 AI: 관광약자를 위한 조건 검증형 영동권 여행 루트 플래너
- **제출**: 12월 7일까지 GitHub 제출. 평가는 GitHub 저장소만 보고 초기 계획서 대비 완성도를 본다(중간평가 없음, 부총리상 추천 후보 12팀 대상). 12월 중 성과공유회.
- **핵심 원칙**: AI는 읽고 판단하고 계획하고 안내문을 만든다. 코드는 계산과 검사를 맡는다. '모름'은 숨기지 않고, 질문과 공식 전화번호로 확인할 방법을 준다. AI 설계의 기준 문서는 [`docs/ai-plan.md`](ai-plan.md) v3다.

## 범위와 확정된 결정

범위는 영동권 관광지, 자동차 이동, 한국어 화면이다.

| 영역 | 결정 |
| --- | --- |
| 지역 | 강릉·속초·동해. 하루 일정 안에서 지역을 넘나들 수 있다 |
| 장소 | 관광지·문화시설만(관광공사 유형 12·14). 음식점·카페·숙박·쇼핑은 추천하지 않는다. 화장실·복지관처럼 관광지가 아닌 곳은 뺀다 |
| 여행 기간 | 달력에서 고른다. 당일, 1박 2일, 2박 3일 |
| 숙소 | 추천하지 않는다. 숙소 지역만 받아 둘째 날부터 출발점으로 쓴다('미정'도 고를 수 있다) |
| 사용자 유형 | 휠체어, 보행이 불편한 어르신, 유모차. 여럿을 함께 고를 수 있고, 유형마다 필수 조건을 적용한다 |
| 이동수단 | 자가용·렌터카 또는 택시. 장애인 전용 주차는 자가용이면서 장애인 표지 차량일 때만 조건이 된다. 장소 사이는 차량으로만 잇고, 걷는 길은 장소 안 정보로 안내한다 |
| 시간 | 영동에 도착한 시점부터 잡는다. 첫날 시작 시각과 마지막 날 마치는 시각을 받고, 중간 날은 09:30\~18:00이 기본이다. 점심·휴식과 승하차 여유를 넣는다 |
| 정보가 없을 때 | '모름'을 허용하되 숨기지 않는다. '모름'은 판단을 막지 않고 확인할 방법을 붙인다. 직원이 바로 답할 수 있는 엘리베이터·장애인 화장실·장애인 주차·출입구·수유실·걷는 거리는 **전화로 물어볼 것**과 공식 전화번호를, 노면·경사·쉴 곳은 **가서 보고 확인할 것**을 붙인다. 화면에는 '적합 · 전화로 확인할 것 있음'처럼 판단과 확인할 것을 함께 보여 준다 |
| 갈 수 없는 곳 | 일정 후보에서 뺀다. 꼭 가고 싶은 곳·대표 관광지·좋아하는 분야 가운데 빠진 곳은 결과 아래 **'이번 조건으로 가기 어려운 곳'**에 이유와 같은 분야의 가까운 대안 하나로 보여 준다 |
| 결과 | 성격이 다른 일정 2\~3개를 먼저 비교하고, 고른 일정을 날짜별로 본다. 2박 3일은 일정 하나를 꼼꼼하게 짠다. 도착 예상 시각은 코드가 계산해 '약'을 붙이고, 날짜마다 '여유 / 빠듯 / 부족'을 판정한다 |
| 고치기 | 장소마다 [바꾸기], 날짜마다 [순서 고치기]로 위·아래 옮기기와 빼기. AI를 다시 부르지 않고 코드가 시각을 다시 계산·검사한다. 다른 날로 옮기기, 자연어 수정, '조건 바꿔 다시 만들기'는 하지 않는다 |
| 확정·공유·인쇄 | 고른 일정을 '이 일정으로 정하기'로 확정하면 확정 일정 페이지(일정 하나와 지도)로 간다. 여기서 읽기 전용 공유 링크를 만들거나 A4 한 장으로 인쇄한다 |
| 날씨 | 확정 일정과 공유 링크에서 날짜마다 그날 가는 시의 기상청 예보(하늘·강수확률·기온)를 보여 준다. 약 10일 뒤까지만 있고, 더 먼 날은 '아직 예보 없음'이다. 강수확률이 60% 이상이면 바깥 장소(바다·해변·자연·산책)에 주의 한 줄을 붙인다. 날씨로 일정을 다시 짜지는 않는다 |
| 저장 | 만든 일정·확정·바꾼 장소·전화 결과는 이 브라우저 탭에만 둔다. 공유할 때만 고른 일정을 서버(Supabase)에 저장한다. 개인정보는 받지 않는다 |
| 화면 | 한국어, 모바일과 PC 반응형. 시작 화면에 '예시 루트 바로 보기'(심사용)를 둔다 |
| 사진 | 공공기관 공식 이미지, 공공누리 1유형을 먼저 쓰고 출처를 표시한다 |
| 지속 가능성 | 운영 비용은 실제로 잰 값만 쓴다(조건 5가지 실측, 일정 한 번에 AI 5회 · 약 50원, [`data/eval/cost-v1.md`](../data/eval/cost-v1.md)). 연계 기관은 협의한 곳이 없으므로 '제안 대상'으로만 쓴다. 코드는 MIT, 데이터·사진은 각 출처의 이용 조건을 따른다 |

## 사용자 유형과 필수 조건

세 유형은 막히는 곳이 달라서 유형마다 필수 조건을 따로 적용한다. 여러 유형을 고르면 항목마다 가장 엄격한 값을 쓴다. 예를 들어 어르신과 유모차를 함께 고르면 걸을 수 있는 거리와 수유실을 모두 본다.

| 항목 | 휠체어 | 유모차 | 보행이 불편한 어르신 |
| --- | --- | --- | --- |
| 계단·단차 없는 진입로 | 필수 | 주의 표시(짧은 단차는 들어서 통과) | 주의 표시(손잡이가 있으면 가능) |
| 엘리베이터(층이 있는 시설) | 필수 | 필수 | 선호 |
| 경사로 기울기 | 필수(급경사 불가) | 선호 | 주의 표시(긴 오르막) |
| 노면(모래·자갈·흙길) | 필수(포장·데크 구간이 있어야 함) | 선호 | 주의 표시(넘어질 위험) |
| 장애인 화장실 | 필수 | — | 선호 |
| 기저귀 교환대·수유실 | — | 선호 | — |
| 장애인 전용 주차구역 | 필수(자가용이면서 표지 차량일 때) | 해당 없음 | 장애 등록 시만(입력에서 선택) |
| 주차장에서 입구까지 거리 | 주의 표시 | 주의 표시 | 필수(입력한 거리 이하) |
| 관람 동선 길이 | — | 선호 | 필수(입력한 거리 이하) |
| 쉴 곳(벤치·쉼터) | — | 선호 | 선호 |
| 휠체어·유모차 대여 | 선호 | 선호 | 선호 |

- **필수**: 하나라도 어기면 후보에서 빠지고 '가기 어려운 곳' 목록으로 간다.
- **선호**: 추천 점수에만 더한다.
- **주의 표시**: 일정에 남기고 장소 카드에 경고를 붙인다.
- **어르신 입력값**: 한 번에 걸을 수 있는 거리(100m / 300m / 500m / 제한 없음)를 받아 주차장→입구 거리, 관람 동선과 비교한다.
- 유형을 고르면 조건이 자동으로 켜지고, 사용자는 하나씩 끄거나 더할 수 있다.

## 사용자 흐름과 화면

입력은 설문처럼 4단계로 나누고 한 화면에는 질문 하나만 둔다. 자유 입력 칸은 없다. 글자는 rem 단위라 휴대폰·브라우저의 글자 크기 설정과 확대를 그대로 따른다.

**사이트 머리줄**: 모든 화면 맨 위에 로고 · '이음길' · '즐거운 영동 여행길', 오늘 영동 날씨(기상청, 강릉 → 속초 → 동해를 3초마다 위로 바꿔 보여 주고 누르면 멈춤, 저장 안 함)와 글자 메뉴(예시 루트 · 관광지 둘러보기 · 서비스 소개, 지금 보는 화면은 밑줄), 오른쪽 끝에 파란 알약 버튼 [여행 루트 만들기]. 버튼은 시작 화면(히어로 버튼·아이콘 띠가 있음)과 입력 화면(4단계 [루트 만들기]와 헷갈림)에서는 숨긴다. 휴대폰은 메뉴를 ☰로 접고 그 안에 '만든 방법'까지 둔다. 시작 화면 아이콘 띠와는 모양(글자 메뉴 / 큰 그림)과 개수를 달리해 겹쳐 보이지 않게 한다(지자체 관광 사이트 9곳이 모두 이렇게 함께 둔다).

**시작 화면**: 디자인 시안과 지자체 관광 사이트 레퍼런스로 만든다.

- 히어로: 영동 풍경 그림(표지판·설악산 바위·정자·흰 길·바다·촛대바위, 흰 길을 따라 점선이 하나씩 찍히고 구름·갈매기·배가 천천히 움직임, 동작 줄이기면 멈춤) 위에 '지도로 찾아가는 즐거운 영동 여행길'(카페24 숑숑)과 한 줄 설명, 주 버튼 '여행 루트 만들기'(초록)와 '예시 루트 먼저 보기'. 오늘 날씨는 11/25부터 머리줄로 옮겼다.
- 바로가기 띠: 여행 루트 만들기 · 예시 루트 보기 · 관광지 둘러보기 · 서비스 소개 · 만든 방법. 아이콘은 히어로와 같은 그림체의 미니 일러스트(표지판 · 지도 · 정자 · 등대 · 설계도)이고, 마우스를 올리거나 키보드 초점이 가면 움직이는 부분만 살짝 움직인다(동작 줄이기면 없음).
- 이렇게 골라요: 단계 3개(조건에 안 맞는 곳은 빼요 / 왜 골랐는지와 출처를 보여 줘요 / 모르는 건 물어볼 것을 알려 줘요)를 고르면 휴대폰 목업 속 화면이 그 단계의 실제 화면으로 바뀐다. 넓고 높은 화면(1024px·높이 700px 이상)에서는 화면을 고정한 채 스크롤로 1→3단계가 넘어간다. 휴대폰·태블릿은 스크롤하면 단계 목록이 화면 위로 지나가 버려서, 휴대폰 목업 바로 아래에 단계 막대(누르면 그 단계)와 지금 단계 카드를 두고 목업이 보이는 동안 3초마다 저절로 넘긴다. 움직이는 내용이라 [자동 넘김 멈추기]가 있고, 단계를 직접 고르면 멈추며, 동작 줄이기 설정이면 멈춘 채로 시작한다. 주 버튼은 '여행 루트 만들기'.
- 누구와 가세요?: 휠체어·강릉 1박 2일 / 어르신·속초 당일 / 유모차·동해 당일 루트 카드 3장. 미리 만든 실제 AI 결과에서 안 하나만 골라 연다(`/trip/route-…`, 안 비교 없음).
- 영동 대표 관광지 8곳을 고화질 사진(CC0 · CC BY · 공공누리 제1유형, 구역 아래 '사진 출처'에 작가 · 라이선스 · 원본 · 바꾼 점)으로 보여 주고, 누르면 관광지 둘러보기에서 그 지역 탭을 고른 채 그 관광지 자세히 창을 연다(`/places?place=ID`, 닫으면 목록의 그 카드가 보인다).

예시 루트(`/trip/example`)와 루트 카드는 저장소에 미리 만들어 둔 실제 AI 결과라 심사위원이 입력 없이(AI 호출 없이) 결과를 볼 수 있다. 처음 들어오면 로고와 한 줄 소개를 잠깐 보여 주고 넘어간다(탭마다 한 번, 누르면 건너뛰고, 움직임 줄이기 설정이면 생략).

**입력 4단계**

1. **언제, 어디서**: 가는 날과 오는 날(당일\~2박 3일), 영동 도착 지점, 이동수단, 자가용이면 장애인 표지 차량 여부. 첫날 시작 시각, 마지막 날 마치는 시각과 떠나는 곳(기본은 도착 지점). 1박 이상이면 숙소 지역을 고르고, 2박 3일은 밤마다 고른다(둘째 밤 기본은 '첫째 밤과 같음'). 숙소를 옮기면 둘째 날은 첫째 밤 숙소에서 출발해 둘째 밤 숙소에서 끝나고, 그날 후보는 양쪽 근처에서 고른다.
2. **누구와**: 휠체어, 보행이 불편한 어르신, 유모차 가운데 여럿을 고를 수 있다.
3. **꼭 필요한 조건**: 유형별 필수 조건이 미리 켜져 있고 끄거나 더할 수 있다. 장애인 전용 주차는 1단계에서 표지 차량을 고른 경우에만 나온다. 어르신을 고르면 한 번에 걸을 수 있는 거리를 고른다.
4. **좋아하는 곳**: 바다·해변 / 자연·산책 / 역사·문화 / 전시·박물관 / 시장·먹거리 / 전망·체험 가운데 여럿, 일정 밀도(여유롭게 / 보통 / 많이), 꼭 가고 싶은 곳(선택). 입력 화면에 "이름·연락처는 받지 않고, 고른 조건은 일정 계산에만 써요"를 보여 준다.

**관광지 둘러보기**(`/places`): 관광지 이름을 다 알지 못해도 강릉·속초·동해 탭과 분야로 둘러본다. 카드에는 큰 대표 사진(4:3), 지역·분야, 이름, 고른 유형 기준 접근성 태그만 두고(휴대폰 1열 · 태블릿 2열 · PC 3열), 어떤 곳인지 한 줄(관광공사 소개를 AI가 미리 정리하고 근거를 검사)과 볼 거리는 [자세히 보기]에 관광공사 소개 원문·운영시간·전화·접근성 10항목과 함께 둔다. **시설로 거르기**([휠체어 진입] [장애인 화장실] [장애인 주차] [엘리베이터] [수유실·기저귀])는 고른 시설이 모두 가능·일부만인 곳만 남기고, 공식 정보가 없는 곳은 빠진다고 알린다. [담기]는 '꼭 가고 싶은 곳'에 넣는다. 대표 관광지를 먼저 보여 준다.

**만드는 중**: 진행률과 단계(조건에 맞는 장소 고르기 → AI 장소 판단 → AI 일정 짜기 → 일정 점검), AI가 살펴보는 장소, 진행 기록("장소 판단 2/3번째 끝", "B안: 운영시간을 넘는 곳이 있어 고치는 중")을 서버에서 받은 그대로 보여 준다. 지난 시간만 보여 주면 실제로 진행 중인지 알 수 없다는 시연 피드백을 반영했다.

**결과 화면** (화면별 상세: [`docs/ai-plan.md`](ai-plan.md) 화면 표)

- **일정 비교**: 성격이 다른 일정 2\~3개를 카드로 쌓는다. 제목, 장소 수, 이동 시간 합계, 전화로 확인할 곳 수를 보여 준다. 제목은 AI가 실제로 넣은 장소·풍경이 드러나게 쓴다(전략 이름 '여유롭게' 같은 말을 되풀이하지 않는다). 갈 곳은 옆 시간표에 다 나오니 카드에는 적지 않는다. 일정을 누르면 그 일정의 상세로 내려가고, 고른 일정·날짜를 바꾸면 지도도 함께 바뀐다. 후보가 적으면 일정 하나만 보여 주고 그렇다고 알린다. 2박 3일은 왜 일정이 하나인지 결과 위에 안내한다.
- **날짜별 탭과 판정**: 고른 일정을 일차별로 보고, "약 5\~6시간 · 여유 있어요"처럼 여유 / 빠듯 / 부족을 보여 준다(코드 계산).
- **지도**: 방문 순서 번호와 짧은 장소 이름, 일반 차량 경로선(구간마다 진행 방향과 이동시간), 출발·도착 표시. 번호를 누르면 사진·시각·판단 카드와 [일정에서 보기]가 뜨고, 일정 카드의 번호를 누르면 지도가 그 장소로 간다. "휠체어 안전 경로가 아닌 일반 차량 경로"라는 안내를 늘 붙인다. 경로선에는 흰 테두리를 두고, 출발·도착 표시는 경로선을 가리지 않게 띄운다. 일정 비교와 확정 일정 페이지에 같은 지도 부품을 쓴다.
- **장소 카드**: 처음에는 사진, 도착 예상 시각, 이름, 판단 칩(적합 / 주의 / 확인 필요)과 확신도, 한 줄 이유, 공식 전화, [바꾸기], [자세히]만 보인다. 사진을 누르면 크게 보고, 사진마다 출처와 편의시설 사진인지를 표시한다. 공식 정보가 없는 항목은 판단 칩 옆에 '공식 정보 없음: 노면'처럼 적는다. [자세히]에는 도착한 뒤 동선, 전화로 물어볼 것, 공공데이터로 확인한 시설, 출처 한 줄이 있다. 한 줄 이유와 같은 말은 다시 쓰지 않는다(주의 상자도 이유와 같으면 띄우지 않는다). 글이 많아 읽기 어렵다는 시연 피드백을 반영했다.
- **구간 이동과 점심**: 카드 사이에 "차량 약 25분 · 14km". 이동 시간은 일정 비교 카드의 합계와 이 구간 줄 두 곳에만 둔다. 시간표 왼쪽 세로선에는 스크롤을 따라 내려가는 진행 원이 있고, 지나간 깃발·번호는 '클리어'로 바뀐다. 일정이 12\~14시에 걸리면 60분 점심·휴식 칸을 둔다(음식점은 추천하지 않음).
- **장소 바꾸기**: 근처 후보 최대 3곳(이름, 판단, 거리, AI 판단 이유)에서 고른다. 그날 시각을 다시 계산하고, 바꾼 카드에 '바꾼 장소 · 원래 ○○'를 붙인다. 되돌릴 수 있다.
- **순서 고치기·빼기**: 날짜마다 [순서 고치기]를 누르면 [↑] [↓] [빼기]로 같은 날 안에서 고친다. 운영시간이나 하루 범위를 넘으면 고치지 않고 이유를 보여 준다. 그날 남은 한 곳은 뺄 수 없고, 꼭 가고 싶은 곳을 빼면 알려 준다. [처음 일정으로] 되돌릴 수 있다.
- **가기 어려운 곳과 대안**: 결과 아래 접는 칸. 꼭 가고 싶은 곳·대표 관광지·좋아하는 분야 가운데 필수 조건 '불가', 걷는 거리 초과, 휴무, AI '부적합'인 곳(최대 5곳)을 이유와 함께 보여 준다. 대안은 같은 분야 15km 안의 갈 만한 곳 하나(적합·주의 먼저)이고, 이유는 ② 판단 이유를 그대로 쓴다. 정보만 보여 준다(누르는 기능 없음).
- **AI 설계 과정 보기**(접힘): 판단 결과 요약, 검사에서 고친 내역, 평가 점수.
- **이 일정으로 정하기**: 출발 전 확인할 것(장소별 질문과 전화) 모음을 띄우고 확정 일정 페이지로 간다.
- **확정 일정 페이지**(`/trip/[id]/final`): 정한 일정 하나, 날짜 탭, 지도, 시간순 목록(시각·이름·판단·전화·가서 볼 것), 출발 전 전화로 확인할 곳([괜찮대요] / [어렵대요], 어려우면 바꾸기). 날짜마다 그날 가는 시의 날씨 한 줄과 기상청 발표 시각, 비·눈 날 바깥 장소 카드에 '비 예보 — 데크·경사로가 미끄러울 수 있어요'. 지도를 못 띄우면 안내 문구만, 경로를 못 받으면 점선 직선으로 잇는다.
- **공유 링크**: [공유 링크 만들기] → 공유 주소, [주소 복사], (휴대폰) [다른 앱으로 보내기], "○월 ○일까지 열려요", 저장하는 것 안내. 받은 사람(`/s/{id}`)은 확정 일정을 읽기 전용으로 본다(바꾸기·공유 버튼 없음, 검색 엔진 제외). 없는 주소나 기간이 지난 주소는 이유와 '이음길에서 내 일정 만들기'를 보여 준다.
- **인쇄·PDF**: 화면 배치 대신 A4 한 장 일정표(날짜별 시간표: 시각·장소·머무는 시간·판단·전화, 출발 전 전화로 물어볼 것과 체크 칸). 사진·지도는 넣지 않고, 1박 2일 기준 1장이다. 공유 링크로 연 화면에서는 링크 주소도 적는다.
- **오류**: 경로를 못 받으면 직선거리 추정치로, AI가 실패하면 규칙 일정 하나와 "AI 응답을 받지 못해 AI 판단 없이 짠 기본 일정이에요"를 보여 준다.

**화면 배치**: 휴대폰(768px 미만)과 태블릿(768px\~)은 한 칸, PC(1024px\~)는 두 칸, 넓은 PC(1280px\~)의 일정 비교는 고르기·상세·지도 세 칸이다. 시작 화면은 PC에서 왼쪽 지도 그림과 오른쪽 문구, 소개 구역은 왼쪽 단계와 오른쪽 휴대폰 목업(화면 고정 스크롤), 입력 4단계는 가운데 질문과 오른쪽 '고른 조건' 요약, 확정 일정은 왼쪽 지도와 오른쪽 일정이다. 바꾸기·확정 창은 휴대폰에서 아래에서 올라오고 PC에서는 가운데 대화창으로 뜬다. 공유 링크로 열면 확정 일정과 같은 배치에서 편집·공유 버튼과 전화 결과 기록만 뺀다.

## 일정을 만드는 방법

AI가 읽고 판단하고 계획하고 안내문을 만들며, 코드는 계산과 검사를 맡는다. 출력 형식(JSON 틀), 검증 규칙, 호출 횟수는 [`docs/ai-plan.md`](ai-plan.md) v3가 기준이다.

**왜 AI가 판단하나**: 관광공사 무장애 정보는 "출입구까지 경사로가 설치되어 있음(완만함)" 같은 짧은 문장뿐이라 코드로는 가능·불가를 가를 수 없다. 기존 사이트는 문장을 그대로 보여 주고 판단을 여행자에게 넘긴다. AI를 빼면 152곳의 데이터를 판단에 쓸 수 없다.

| 일 | 언제 | 받는 것 | 내놓는 것(JSON) | 코드가 강제하는 것 |
| --- | --- | --- | --- | --- |
| ① 읽기 | 미리, 152곳 | 장소별 API 문장 | 접근성 값·메모·근거·질문, 운영시간, 도착 후 동선 초안 | 스키마·근거 id 검사, 두 번 읽어 일치율 |
| ② 판단 | 요청할 때 | ① 결과, 원문, 사용자 조건 | 적합 / 주의 / 부적합 / 확인 필요, 이유, 근거, 확신도 | 안전 하한, 3번 판단해 확신도 |
| ③ 계획 | 요청할 때 | 적합·주의 장소 먼저, 모자라면 확인 필요(표시), 이동시간 표, 운영시간, 화장실 위치 | 성격이 다른 일정 2\~3개(장소·순서·머무는 시간·이유·주의·질문) | 시각 계산, 운영시간·하루 범위 검사, 걸린 일정만 다시, 통과한 일정만 노출 |
| ④ 안내 | 미리 | 동선 초안, 판단 이유 | 도착 후 동선(① 결과), 출발 전 확인할 것(체크리스트), 대안 이유(② 판단 이유) | 대안 장소는 코드가 고름, 전화로 물을 것과 가서 볼 것은 코드가 나눔 |

**미리 하는 일(스크립트)**: ① 읽기에서 152곳의 문장(무장애·소개·반복·개요)을 AI가 읽어 접근성 10항목 값(가능 / 부분가능 / 불가 / 모름)과 메모·근거, '모름'이면 질문, 운영시간과 휴무, 도착 후 동선 초안을 만든다. 사람이 확인한 값이 생기면 등급 `human`으로 덮어쓴다.

**요청할 때**(`POST /api/plan`, 진행 상황을 스트리밍)

1. **후보 거르기(코드)**: 지역 밖, 그날 휴무, 필수 조건이 '불가'인 곳을 빼고 최대 20곳(2박 3일은 30곳)을 고른다.
2. **② 판단(AI)**: 후보를 한 호출에 묶어 3번 판단한다. 이어서 코드가 안전 하한을 적용한다(아래 원칙).
3. **이동시간 표**: AI에게는 직선거리로 어림한 표를 준다. 후보를 모두 카카오로 짝지으면 호출이 너무 많기 때문이다. 다 짠 일정은 날짜마다 카카오 다중 경유지 길찾기 1회로 실제 구간 시간을 받아 다시 검사하고, 넘치면 코드가 시간을 맞춘다. 카카오 값은 이 검사에만 쓰고 버린다.
4. **③ 계획(AI)**: 한 호출로 방향이 다른 일정 2\~3개를 받는다. 시각은 쓰지 않는다. 2박 3일은 일정 하나다.
5. **시각 계산과 검사(코드)**: 이동 + 머무는 시간 + 유형별 여유(휠체어·어르신 25%) + 승하차 여유(휠체어 10분, 구간마다 주차·승하차 5분) + 12\~14시 점심 60분으로 시각을 계산한다. 운영시간, 하루 범위, 머무는 시간 범위, 꼭 가고 싶은 곳이 모든 일정에 있는지를 검사한다. 몇 분만 넘친 일정은 코드가 맞춘다(머무는 시간을 권장 최소로 → 뒤쪽 장소를 최대 2곳 빼기, 꼭 가고 싶은 곳은 남김).
6. **다시 받기와 평가**: 검사에 걸린 일정만 위반 내용을 돌려줘 다시 받는다(최대 2회). 평가자 AI가 피로도·여유·취향·화장실 간격을 1\~5점으로 보고, 2점 이하면 한 번 고친다. 일정끼리 장소가 절반 넘게 겹치면 다시 만든다. 끝까지 통과하지 못한 일정은 뺀다.
7. **④ 안내**: 도착 후 동선은 ① 읽기 결과를 카드에, 출발 전 확인할 것은 확정 화면 체크리스트로 보여 준다. 장소 바꾸기 후보와 가기 어려운 곳의 대안은 코드가 고르고 ② 판단 이유를 그대로 쓴다.
8. **실패하면 규칙 일정**: AI가 실패하면 아래 규칙 일정 하나를 보여 준다.
9. **경로선**: 확정 일정 페이지를 열 때 날짜마다 다중 경유지 길찾기를 한 번 부른다(`/api/route-line`, 저장 안 함).

AI 호출은 요청 한 번에 약 5\~8회(판단 3, 계획 1, 다시 받기 0\~2, 평가 1\~2)이고, 카카오 길찾기는 날짜마다 1회(다 짠 일정의 실제 구간 시간을 다중 경유지 길찾기 한 번으로)다. 확정 화면을 열 때도 날짜마다 1회로 실제 이동시간·경로선을 다시 받는다.

**원칙**

- **JSON으로만 받는다**: 모든 출력은 스키마(ajv)로 검사한다. 형식이 틀리면 한 번 다시 받고, 그래도 틀리면 버린다.
- **근거 없는 말은 버린다**: 넘겨준 문장의 근거 id가 없는 판단·문장은 쓰지 않는다. 입력에 없는 시설·시간·거리를 쓰지 않는다. 빈칸은 '모름'이다.
- **시각은 코드가 쓴다**: 화면의 "10:30 도착"은 모두 코드가 계산한 값이다. 날씨 문구도 코드에 고정된 글이다.
- **안전 하한은 코드가 정한다**: 필수 조건이 '불가'면 부적합, '부분가능'이면 최소 주의, 휠체어는 '들어갈 수 있다'는 원문이 없으면 확인 필요다. 그 밖의 '모름'은 질문과 전화번호로 붙인다. AI는 더 보수적으로만 바꿀 수 있다.
- **개인정보를 보내지 않는다**: Gemini 무료 등급은 보낸 내용이 학습에 쓰일 수 있다. 입력 조건과 장소 정보만 보내고, 자유 입력 칸이 없어 이름·연락처가 들어갈 길이 없다. OpenAI는 `store: false`로 보낸다.
- **실패해도 멈추지 않는다**: 시간 초과, 형식 오류, 호출 한도면 규칙 일정 하나를 보여 준다.
- **제공자를 바꿀 수 있다**: AI 호출은 `src/lib/llm.ts` 한 파일로 묶고 모델명은 환경변수로 둔다. Gemini(`gemini-3.5-flash-lite`)를 먼저 쓰고, 붐비거나(503·429) 30초 넘게 늦으면 같은 요청을 OpenAI(`gpt-6-luna`)에도 보내 먼저 온 답을 쓴다. 요청 전체는 90초 안에 끝낸다.

**고칠 때**: 장소 바꾸기, 순서 바꾸기, 빼기는 AI를 다시 부르지 않고 화면에서 코드가 시각 계산과 검사만 다시 돌린다. 경로선과 실제 이동시간은 화면을 열 때 다시 받는다. 카카오는 길찾기 결과를 저장해 두고 다시 쓰는 것을 금지하므로, 공유 링크에는 일정 JSON(장소·순서·머무는 시간·이유)만 저장하고 열 때 이동시간·시각·경로를 다시 계산한다.

<details>
<summary>규칙 일정(AI가 실패할 때 쓰는 대체 경로, AI 일정의 검사 기준으로도 씀)</summary>

1. **후보 걸러내기**: 영동권 전체에서 고른 유형의 필수 조건을 어기는 곳, 그날 휴무인 곳을 뺀다. 장애인 전용 주차 조건은 자가용이면서 장애인 표지 차량일 때만 켠다. 빠진 곳 가운데 취향에 맞는 곳은 '가기 어려운 곳' 목록으로 보낸다.
2. **점수 매기기**: 취향 일치, 선호 조건 충족 개수, 도착 지점과의 거리. 꼭 가고 싶은 곳은 항상 넣는다.
3. **개수 정하기**: 반나절 2\~3곳, 하루 3\~5곳. 일정 밀도가 하한·중간·상한을 고른다. 휠체어·어르신이 '많이'를 고르면 하루 4곳까지다. 조건을 통과한 장소가 모자라면 그날 장소 수를 줄이고 그렇다고 알린다.
4. **날짜별 배분(1박 이상)**: 장소를 지역 단위로 묶어 날짜에 나눈다. 첫날은 도착 지점 쪽, 다음 날부터는 숙소 지역 쪽 묶음부터 채운다. 같은 장소는 한 번만 넣는다. 중간 날은 숙소 09:30 출발\~18:00 도착이 기본이고, 마지막 날은 떠나는 곳에서 끝난다. 숙소가 '미정'이면 첫날 마지막 장소 근처를 숙소로 가정하고 그렇게 표시한다.
5. **순서 정하기**: 장소가 5곳 이하라 가능한 순서를 모두(최대 120가지) 계산하고, 총 이동시간과 운영시간 위반 벌점이 가장 낮은 순서를 고른다. 순서를 정할 때는 직선거리 추정을 쓰고, 정해진 순서의 실제 구간 시간은 다중 경유지 길찾기 1회로 받는다.
6. **시간 범위 계산**: 총 이동시간 + 장소별 권장 머무는 시간의 합 + 유형별 여유. 휠체어를 고르면 장소마다 승하차 여유를, 일정이 12\~14시에 걸리면 점심·휴식 60분을 더한다.
7. **판정**: 범위 최댓값이 여행 시간 안이면 여유, 최솟값만 들어오면 빠듯, 최솟값도 넘으면 부족(점수가 가장 낮은 1곳을 뺀 일정을 함께 제시). 1박 이상이면 날짜마다 따로 판정한다.
8. **운영시간 검사**: 늦은 쪽 도착 예상 시각이 입장 마감을 넘으면 경고하고, 이른 쪽도 넘으면 순서에서 뺀다. 여행 날짜에 맞춰 하절기·동절기 운영시간과 명절 휴무를 고른다.

## 데이터

장소 데이터는 저장소 안 `data/places.json` 하나로 둔다. 관광공사 API 기본 정보, ① 읽기 결과(등급 `ai`), 공중화장실 공공데이터(등급 `public`), 사람이 확인한 값(등급 `human`)이 들어가고, 심사위원이 GitHub에서 바로 볼 수 있다. 빌드할 때 형식 검사(JSON Schema)를 돌린다. 장소별 근거 문장은 `data/docs/places/{id}.md`(문단 id와 출처 URL)에 두고, API 원본(`data/raw/`)은 커밋하지 않는다. 서버(Supabase)에는 공유된 일정만 저장한다.

**access 항목**(조건표와 1:1): step\_free\_entrance, elevator, slope, surface, accessible\_toilet, diaper\_nursing, disabled\_parking, rest\_area, rental\_wheelchair, rental\_stroller. 값은 `가능 / 부분가능 / 불가 / 모름` 가운데 하나다.

- **빌드 검사**: '모름'에 질문이 없거나, '부분가능'에 메모(예: "해변 데크까지 가능, 모래사장 진입 불가")가 없거나, 장소에 전화번호가 없으면 빌드가 실패한다. 빈칸을 지어내지 않고 확인할 방법을 반드시 붙이기 위해서다.
- **빈칸**: API에 없는 항목(쉴 곳, 주차장→입구 거리, 관람 동선 길이)과 대부분 비어 있는 항목(노면, 경사)은 '모름'으로 시작하고 질문과 공식 전화번호를 붙인다. 사람 판정은 하지 않는다.
- **출처 표시**: 항목마다 출처를 달아 관광공사 API, 열린관광, 지자체 페이지, 현장 사진, 전화 확인(날짜·기관)을 구분한다.
- **야외 시설**: 관광공사 분류가 자연관광·도시공원이면 층이 없는 야외 시설로 보고 엘리베이터를 '가능'으로 둔다(코드 규칙, 근거 `class-1`).
- **사진**: 공공누리 1유형을 먼저 쓴다. 1유형은 작게 잘라 `public/photos/`에 저장하고, 3유형(변경 금지)은 원본을 자르지 않고 통째로 보여 준다. 화장실 같은 편의시설 사진은 대표 사진으로 쓰지 않고 크게 보기에서 "편의시설 사진"으로 표시한다. 분류 결과는 `data/photos.json`(사진 출처 목록 겸용)이다.

## 기술과 외부 API

Next.js 하나로 화면과 서버 API를 만든다. 서비스가 부르는 외부 서비스는 카카오, Gemini(늦으면 OpenAI), Supabase(공유 링크), 기상청 예보(날씨)다. 관광공사 API와 공중화장실 데이터는 데이터를 만드는 스크립트에서만 쓴다. OpenAI 말고는 모두 무료 등급 범위다.

| 구분 | 선택 | 쓰임 | 주의할 점 |
| --- | --- | --- | --- |
| 프레임워크 | Next.js(App Router) + TypeScript | 화면과 서버 API(키 숨김) | — |
| 스타일 | Tailwind CSS v4 + shadcn/ui | 반응형, 큰 글씨, 고대비 | 글꼴은 Pretendard와 카페24 숑숑(시작 화면 문구만) 두 가지. 둘 다 SIL OFL 1.1이고 자체 호스팅 |
| 지도 | 카카오맵 JavaScript SDK | 번호 표시, 경로선 | 무료 쿼터는 개발자 계정에서 처음 활성화한 앱에만 주어진다. 앱을 하나로 고정하고 Vercel 도메인을 등록 |

## 검증

조건을 어기는 장소가 일정에 들어가지 않는지, AI 답을 코드가 제대로 거르는지를 자동 테스트로 고정한다. 모든 커밋마다 GitHub Actions가 장소 데이터 검사, 단위 테스트, 린트, 빌드, 화면 흐름 테스트(모바일·PC)를 돌린다.

- **엔진**: 아래 시나리오 10개와 세 유형의 모든 조합 7가지 × 이동수단 2가지 = 14가지(2박 3일)에서 필수 조건 위반 0건.
- **AI 가드**: 가짜 AI로 근거 없는 판단을 버리는지, '모름'을 적합으로 바꾸지 않는지, 시각을 코드 값으로 쓰는지, 실패하면 규칙 일정이 나오는지 검사한다.
- **AI 평가**(사람 정답 없이 자동으로 잴 수 있는 일관성 지표, [`data/eval/`](../data/eval/)): ① 읽기에서 근거 없이 채운 값 0건, 두 번 읽어 96.4% 일치. ② 판단을 3번 했을 때 셋 다 같은 비율 Gemini 85.7% · OpenAI 78.3%, 두 모델이 정반대로 판단한 경우 0건. 정확도가 아니라 **일관성** 지표라는 점을 README에 그대로 밝힌다.
- **웹 접근성**: axe-core 자동 검사(WCAG 2.2 A·AA)로 주요 화면을 휴대폰·PC에서 확인한다. 색은 파랑 #3580db · 초록 #3daa7e 두 가지로 통일하고, 글자 대비 규칙은 팀 결정으로 검사하지 않는다(11/24).
- **사용자 테스트**: 팀원(강환일)이 실제 이용자 입장에서 화면을 계속 써 보며 불편한 점과 버그를 찾는다.

## 위험과 대응

공공데이터를 받아 '장소가 0곳'인 위험은 사라졌다. 남은 큰 위험은 AI 판단의 정확도와 무료 호출 한도다.

| 위험 | 대응 |
| --- | --- |
| 확인되지 않는 항목이 남음 | '모름'으로 두고 질문과 공식 전화번호를 붙인다. 적합·주의여도 물어볼 것이 있으면 '전화로 확인할 것 있음'을 칩에 함께 표시한다 |
| 노면·경사·거리가 거의 없어 휠체어·어르신은 대부분 '확인 필요' | 확인 필요 장소도 일정에 넣되 질문과 전화번호로 분명히 표시한다. 사람 판정은 하지 않고 사용자가 출발 전에 확인할 수 있게 한다 |
| AI가 문장을 잘못 읽음 | 근거 없는 값은 코드가 '모름'으로 바꾼다. 두 번 읽은 일치율로 흔들리는 항목을 찾아 지시문을 고친다. 화면에 'AI 정리' 등급과 근거 원문을 함께 보여 준다 |
| 카카오 길찾기 오류·한도 | 직선거리 × 보정계수로 임시 이동시간을 보여 주고 "추정"으로 표시한다 |
| Gemini 한도 초과·혼잡(시연 중) | 붐비거나 30초 넘게 늦으면 OpenAI로 같은 요청을 보내고, 요청 전체를 90초 안에 끝낸다. 둘 다 안 되면 규칙 일정 하나. ① 읽기는 미리 돌려 두고, 판단은 후보를 한 호출에 묶는다 |
