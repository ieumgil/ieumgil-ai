# AI 활용 계획 (후보 정리, 미확정)

> claude.ai 대화(2026-11-10)에서 나온 내용을 Claude Code로 넘기기 위해 정리한 문서.
> **아직 확정이 아니다.** 사용자가 번호를 고르면 확정 섹션을 채우고 CLAUDE.md 원칙을 함께 고친다.

## 왜 필요한가

- 중간평가 항목: 문제 정의·필요성 20 / **AI 활용 적정성 및 실현 가능성 25** / 진행률·팀 활동 성실도 20 / 혁신성·창의성 15 / 지속가능성 20
- 현재 구조("규칙이 판정, LLM은 설명만")는 화면에서 AI가 결과 밑 설명 몇 줄로만 보여 "AI를 빼도 돌아가는 서비스"로 읽힐 위험이 있다.
- 점수 기준은 '많이'가 아니라 '적정하게'다. AI를 판정에 넣지 않고, 틀려도 위험하지 않은 자리에 넓게 넣는다.

## 바꿀 원칙 (확정되면 CLAUDE.md에 반영)

- 현재: 판정은 규칙이 하고, LLM은 설명만 한다.
- 변경안: **판정은 규칙이 한다. AI는 데이터 추출·조건 추출·후보 선택 보조·설명을 맡는다.**
- **AI의 판단은 일정을 더 안전한 쪽으로만 바꿀 수 있다.** 장소 제외, 경고 상향은 허용. 규칙이 막은 장소를 살리거나 경고를 내리는 것은 금지.
- 구조 한 줄: "AI가 제안하고 규칙이 거부권을 가진다."
- AI가 실패하면(호출 한도, 지연, 형식 오류) 규칙만으로 일정이 나와야 한다.
- 사용자 입력이 Gemini로 가는 기능은 "이름·연락처는 적지 마세요" 안내와 서버의 연락처 패턴 제거가 필수(무료 등급은 입력이 학습에 쓰일 수 있음).

## AI가 판정하지 않는 이유

- 장소의 실제 접근성(턱, 계단)을 AI는 알 수 없다. 결국 우리 데이터를 다시 읽는 것이라 정확도는 오르지 않고 틀릴 가능성만 생긴다.
- 같은 입력에 다른 답 → 엔진 테스트를 고정할 수 없다.
- 틀렸을 때 피해가 크다(휠체어 사용자가 계단을 만남).
