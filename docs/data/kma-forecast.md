# 기상청 단기·중기예보 API 정리

확정·공유 화면의 날짜별 날씨(하늘·강수확률·기온)와 비·눈 날 바깥 장소 주의에 쓰는 기상청 예보의 명세와 우리가 쓰는 범위를 정리한 문서다.
값은 공식 활용가이드와 공공데이터포털 상세 페이지에서 확인한 것이고, 실제 키로 확인하지 못한 부분은 **[ASSUMED]**로 표시한다(맨 아래 표).
날씨는 서버(`/api/weather`)에서만 부르고 저장하지 않는다. 키는 환경변수 `KMA_API_KEY`에만 있다.

## 1. 데이터셋과 게이트웨이

| 이름 | 공공데이터포털 | 서비스 경로 | 오퍼레이션 |
|---|---|---|---|
| 기상청 단기예보 조회서비스 | [15084084](https://www.data.go.kr/data/15084084/openapi.do) | `VilageFcstInfoService_2.0` | `getVilageFcst` |
| 기상청 중기예보 조회서비스 | [15059468](https://www.data.go.kr/data/15059468/openapi.do) | `MidFcstInfoService` | `getMidLandFcst`(육상) · `getMidTa`(기온) |

게이트웨이는 둘이고 한 환경변수로 고른다(`KMA_GATEWAY`, 기본 `portal`).

| 이름 | 주소 | 키 파라미터 |
|---|---|---|
| portal(기본) | `https://apis.data.go.kr/1360000/` | `serviceKey` |
| apihub | `https://apihub.kma.go.kr/api/typ02/openApi/` | `authKey` |

- 단기·중기는 포털에서 각각 활용신청해야 한다. 일일 한도는 개발계정 10,000건(두 API 모두).
- 키는 Encoding(`%2B`) 또는 Decoding(`+`) 모양으로 발급된다. 코드는 한 번만 인코딩하도록 정리한 뒤(`normalizeKey`) 보낸다.
- 어느 게이트웨이가 이 키를 받는지는 `npx tsx scripts/dev/weather-probe.ts`로 확인한다(6절).

## 2. 발표 시각과 예보 기간

| 구분 | 발표 | 제공 시작 | 예보 기간 |
|---|---|---|---|
| 단기 | 02·05·08·11·14·17·20·23시 (`base_time` 0200…2300) | 발표 +10분 | 02~14시 발표분은 오늘~D+3(글피), 17·20·23시 발표분은 오늘~D+4(그글피) |
| 중기 | 06·18시 (`tmFc` `YYYYMMDD0600` / `…1800`, 최근 24시간 자료만) | 가이드에 지연 시각 없음 | 06시 발표분은 D+4~D+10, 18시 발표분은 D+5~D+10 |

- 단기 예보 기간은 2024-11-28 연장 이후 기준이다(연장 전 "모레까지"라는 옛 값은 쓰지 않는다).
- 중기 필드 이름의 숫자(`wf4Am`, `taMin7` …)는 **발표 날짜 + N일**이다(오늘 + N일이 아니다). 날짜는 `tmFc`에서 센다.
- 코드는 단기 발표를 `pickShortBase`(발표 +15분 뒤부터), 중기 발표를 `pickMidTmFc`(발표 +30분 뒤부터)로 고르고, 데이터 없음(03)이면 한 칸 앞 발표로 한 번만 다시 부른다.
- 단기와 중기가 겹치는 날은 **단기를 우선**한다.

## 3. 쓰는 항목과 안 쓰는 항목

| 서비스 | 쓰는 항목 | 뜻 |
|---|---|---|
| 단기 | `SKY` | 하늘 1 맑음 · 3 구름많음 · 4 흐림 |
| 단기 | `PTY` | 강수형태 0 없음 · 1 비 · 2 비/눈 · 3 눈 · 4 소나기 |
| 단기 | `POP` · `TMP` · `TMN` · `TMX` | 강수확률(%) · 1시간 기온 · 하루 최저 · 하루 최고(℃) |
| 중기 육상 | `rnSt4Am`~`rnSt7Pm` · `rnSt8`~`rnSt10` | 강수확률(4~7일은 오전·오후, 8~10일은 하루 한 값) |
| 중기 육상 | `wf4Am`~`wf7Pm` · `wf8`~`wf10` | 날씨 문장(맑음·구름많음·흐림, "구름많고 비" 같은 형태) |
| 중기 기온 | `taMin4`~`taMin10` · `taMax4`~`taMax10` | 최저·최고 기온(정수 ℃) |

- 안 쓰는 것: 단기 `PCP`(강수량)·`SNO`(적설)·`WSD`(풍속) 등 — 화면에는 하늘·강수확률·기온만 보여 주고, 연장 구간에서는 값이 정성 코드로 바뀌어 섞이면 오해하기 쉽다.
- 결측: 절댓값 900 이상은 비어 있는 값으로 보고 버린다.
- `TMN`·`TMX`는 발표 시각에 따라 들어 있는 날이 다르다. 없으면 그날 `TMP`의 최솟값·최댓값으로 대신한다.

## 5. 응답 모양과 오류 코드

세 가지 모양이 있고 HTTP 상태만 보면 안 된다(`readEnvelope`가 모두 처리한다).

1. 정상: `response.header.resultCode == "00"` + `response.body.items.item[]`(항목이 하나면 배열이 아닐 수 있다)
2. 포털 게이트웨이 오류: `OpenAPI_ServiceResponse.cmmMsgHeader.returnReasonCode`(HTTP 4xx/5xx)
3. API허브 오류: `result.status`(예: 401)

| 코드 | 뜻 |
|---|---|
| 00 | 정상 |
| 03 | 데이터 없음(발표가 아직 안 올라옴 등 — 직전 발표로 한 번 다시 부름) |
| 10·11·12 | 요청 파라미터 오류 · 필수 파라미터 없음 · 없는 서비스 |
| 20·21·22 | 접근 거부 · 키 일시 중지 · 일일 호출 한도 초과 |
| 30·31·32·33 | 등록되지 않은 키(이중 인코딩일 때도 이 코드) · 기간 만료 · 등록되지 않은 IP · 서명 없는 호출 |
| 99 | 알 수 없는 오류 |

오류 메시지·로그에는 코드만 남기고 요청 주소와 키는 넣지 않는다.

## 6. 하루 대표값 규칙

- 낮 창은 06~21시(여행 활동 시간). 강수확률은 창 안 최댓값, 하늘은 창 안 최빈값(동률이면 더 흐린 쪽).
- 강수 형태는 창 안 `PTY`로 정한다: 눈만이면 눈, 비/눈이 있거나 비·눈이 섞이면 비/눈, 그 밖은 비. `PTY`가 모두 0이어도 강수확률이 60% 이상이면 안전 쪽으로 비로 본다.
- 오늘은 이미 지난 시각의 행을 빼고, 창에 행이 하나도 없으면 그날은 표시하지 않는다.
- 중기는 4~7일은 오전·오후 중 강수확률이 큰 쪽을 쓰고, 날씨 문장을 모르는 값이면 그날은 표시하지 않는다. 기온 호출이 실패해도 하늘·강수확률만으로 보여 준다.
- 범위: 오늘~약 10일 뒤. 그 밖의 날은 "아직 예보 없음", 지난 날은 예보를 보여 주지 않는다.
- 주의: 바깥 장소(바다·해변, 자연·산책)에만, 그 시의 그날 강수확률이 60% 이상일 때 한 줄. 폭염·한파·강풍 주의는 하지 않는다.
- 날씨 글은 코드가 정한 고정 문구뿐이다. AI는 날씨를 읽거나 쓰지 않는다.

## 7. 캐시와 저장

- 서버에서만 부른다(`/api/weather`). 브라우저에 키가 나가지 않는다.
- 서버 캐시는 `'use cache'`로 15분 뒤 다시 확인하고 30분 뒤 만료한다(`revalidate: 900`, `expire: 1800`). 응답 헤더는 완전한 응답(`complete: true`: 세 시의 단기와 중기 호출이 모두 성공했거나 데이터 없음으로 확정)만 `s-maxage=900, stale-while-revalidate=300`이고, 일부 호출이 실패한 응답은 `s-maxage=60`, 날씨가 하나도 없으면 `no-store`다. 내부 캐시와 CDN을 합쳐도 1시간 안쪽이다.
- 데이터 없음(03)은 1~2분만 캐시한다. 다시 불러도 소용없는 오류(12·20 활용신청 누락, 22 호출 한도, 30·31·32 키 문제)는 30~60초만 캐시하고 재시도하지 않아, 요청마다 기상청을 다시 부르지 않는다. 그 밖의 실패(네트워크·시간 초과)는 캐시에 굳히지 않는다(A7로 확인 대상).
- 기온이 단기예보의 최저·최고(TMN·TMX)가 아니라 시간별 기온(TMP)으로 채운 값이면 화면에 '약 8~14℃'처럼 '약'을 붙인다. 오늘 오후에 열면 지난 시각이 빠진 남은 시각의 값이라 이 경우가 된다.
- 공유 문서·Supabase·탭 보관에는 날씨를 저장하지 않는다. 화면을 열 때마다 받아 메모리에서만 쓴다.
- 호출이 실패하거나 키가 없으면 날씨 칸만 숨기고 일정은 그대로 보여 준다.

## 9. 아직 확인하지 못한 것 [ASSUMED]

실제 키로 응답을 받아 보기 전이라 아래는 공식 문서와 가짜 키 응답에서 추정한 값이다. 시험용 응답(`tests/fixtures/weather/`)도 공식 활용가이드 예제를 본떠 만든 값이다.

| 번호 | 가정 | 어긋나면 |
|---|---|---|
| A1 | JSON 응답이 가이드의 XML 예제와 같은 구조다(`response.body.items.item[]`) | 읽는 코드 수정 |
| A2 | 데이터 없음은 결과 코드 03(또는 빈 항목)으로 온다 | 특정 시각대 날씨가 빠질 수 있음(무해) |
| A4 | 같은 계정의 인증키가 단기·중기 모두에 쓰인다(각각 활용신청 필요) | 코드 30이 나오면 날씨 칸 숨김 |
| A5 | 중기 `tmFc`는 발표 30분 뒤부터 쓸 수 있다 | 직전 발표로 한 번 다시 불러 흡수 |
| A7 | 'use cache' 안에서 던진 오류는 캐시에 저장되지 않는다 | 실패가 길게 굳을 수 있어 짧은 캐시로 분기 |
| A8 | 포털 게이트웨이가 사용자 키를 받는다(2610 가이드는 API허브를 안내) | 기본 게이트웨이를 apihub로 바꿈(`KMA_GATEWAY`) |
| A9 | 디지털 중기예보 개편(2026-11) 뒤에도 기존 중기 API가 당분간 유지된다 | 중기 구간만 "아직 예보 없음" |

확인 방법: 키를 받은 뒤 `npx tsx scripts/dev/weather-probe.ts`를 한 번 돌리면 포털·API허브 두 게이트웨이에서 세 오퍼레이션이 되는지 줄마다 보여 준다.
`--save`를 붙이면 키를 지운 응답이 `tests/fixtures/weather/live/`에 저장되어 시험용 응답을 실제 값으로 바꿀 수 있다. 프로브는 키·요청 주소·응답 원문을 출력하지 않는다.

### 개편 위험

기상청은 2026-11 디지털 중기예보 개편을 알렸다. 개편 뒤 중기 오퍼레이션의 이름·필드가 바뀌면 중기 구간(D+4~D+10)만 "아직 예보 없음"으로 보이고 단기 구간은 그대로 동작한다.
