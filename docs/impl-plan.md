## 정한 것 (11/10)

- **Gemini 무료 등급으로 시작**(당분간 개발자 혼자 사용). 한도가 부족하면 유료 Tier 1로 바꾼다.
- 모델은 환경변수로 둔다.
  - `GEMINI_MODEL_FAST`(요청할 때 ②③④, 기본 `gemini-3.5-flash-lite`)
  - `GEMINI_MODEL_READ`(미리 하는 ① 읽기, 기본 `gemini-3.8-flash`, 실패 시 FAST로 대체)
  - 무료 한도는 공식 수치가 없고 AI Studio 화면에서 확인한다(비공식 10월 측정: Flash 5 RPM·20 RPD, Flash-Lite 15 RPM·500 RPD).
- **공유 링크·Supabase는 나중에.** 메인 기능(입력 → AI 판단 → 일정 2~3안 → 비교·상세)에 집중한다. 예시 루트는 저장소의 JSON 파일로 둔다.
- SDK: `@google/genai` 3.0.0, `client.interactions.create({ response_format: { type: "text", mime_type: "application/json", schema } })`.
  스키마는 일부 키워드만 지킨다(`minLength` 등은 무시) → 앱에서 ajv로 다시 검사한다.

## 판단 규칙 개정 (11/10)

질문은 "이 사람이 여기서 관광할 수 있나" 하나. 코드는 원문상 '불가'(부적합)·'부분가능'(최소 주의)·알려진 걷는 거리 초과만 강제하고,
'모름'은 판단을 막지 않고 출발 전 확인 질문으로 붙인다. 휠체어는 '들어갈 수 있다'는 원문(진입)이 있어야 적합.
LLM이 실패했을 때의 규칙 판단은 엄격(필수 '모름'이 있으면 확인 필요). ① 다시 읽기(예시 추가)로 경사 '모름' 17곳이 '가능'으로, 이전 결과와 항목 일치율 96.4%.

## 디자인 점검 (11/11)

대비 부족 3곳, 버튼 포커스 테두리, 지도 캡션이 축척 가림, '확인' 용어(판정 '확인 필요' vs 질문 '전화로 물어볼 것', 안 비교의 '전화 확인 N곳'),
판정 칩 '적합 · 전화로 확인할 것 있음'(11/10 판단 규칙 그대로, 문서 문구 정리), 장소 카드 정보 덜기, 바꾸기 결과 알림,
확정 창 줄이기, 확정 화면 전화 확인 체크리스트(괜찮대요/어렵대요 → 바로 바꾸기, 출발 준비 끝, 인쇄), 안 비교 세로 배치·안 바꿀 때 알림.
남은 작은 것: 바꾸기 후보 버튼 무게, 확정 화면에 '도착하면' 동선, 안전 각주 위치.

## 추가 계획 (11/10)

### 공유 링크 — 확정 일정 + 지도를 다른 사람과 함께 보기

- 확정 일정 페이지에 **[공유 링크 만들기]** → 짧은 무작위 주소(`/s/{id}`)를 만들고 복사한다. 받은 사람은 로그인 없이 **읽기 전용**으로 지도 + 일정 + 출발 전 확인할 것을 본다.
- 저장(Supabase `trips`, 서버에서만 쓰기): 안 JSON만 — 장소·순서·체류·이유·주의·확인 질문(바꾼 장소 반영), 날짜, 유형, 하루 틀. 
  **카카오 이동시간·경로선은 저장하지 않고** 열 때마다 다시 계산한다(캐싱 금지). 이름·연락처·IP 없음.
- **자동 폐기**: 만료 시각을 함께 저장하고, 매일 한 번 지난 것을 지운다(Supabase 예약 작업 또는 Vercel Cron). 
  지워지기 전이라도 만료가 지난 링크는 "기간이 지난 일정이에요"만 보여준다. 만료 기준은 정할 것(예: 여행 마지막 날 + 7일, 최대 30일).
- 할 일: Supabase 프로젝트·테이블·정책(읽기는 id로만, 쓰기는 서버만), `POST /api/trips`(만들기) · `/s/[id]`(보기) · 만료 정리 작업, 
  E2E(만들기 → 열기 → 만료 후 안내), 저장 내용에 카카오 결과·개인정보가 없는지 테스트.
