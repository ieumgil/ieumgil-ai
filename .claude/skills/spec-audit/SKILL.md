# 요구사항 정밀 검토 (이음길)

검토 대상: $ARGUMENTS
(비어 있으면 `.planning/STATE.md`의 현재 단계, 그것도 없으면 사용자에게 묻는다.)

**코드와 문서를 고치지 마라.** 읽고 보고만 한다.

## 먼저 읽을 것
1. `CLAUDE.md` — 절대 원칙 6개, 유형별 필수 조건, 일정 로직 순서, 디자인 토큰
2. `docs/planning.md` — 기획 기준 문서(조건표, 일정 로직 11단계, 엔진 시나리오 10개)
3. `docs/handoff.md` — 열린 결정 목록(여기 있는 건 Claude가 정하지 않는다)
4. `docs/ai-plan.md` — AI 활용 후보(미확정이면 현재 원칙 유지)
5. `.planning/` 문서(있으면) — 해당 단계의 CONTEXT·PLAN·UI-SPEC
6. 관련 코드: `src/lib/engine/`, `src/lib/types.ts`, `src/lib/plan/`, `data/places.schema.json`, `tests/`

## 이음길 원칙 점검 (하나라도 어기면 차단 이슈)
- **LLM이 읽고·판단하고·계획하고·풀어준다, 코드는 계산과 검사만 강제** (`docs/ai-plan.md` v3).
  - LLM 출력을 JSON 스키마로 검사하지 않고 화면·저장에 쓰는 경로가 있는가?
  - 근거 id가 없거나 넘겨준 문장 밖인 판단·문장이 버려지지 않고 쓰이는가?
  - 안전 하한: 필수 '불가'가 부적합이 아닌 채로, '모름'이 '적합'으로, '부분가능'이 '적합'으로 나갈 수 있는가? 2:1에서 보수적인 쪽을 쓰는가?
  - LLM이 시각을 쓰거나, 검사를 통과하지 않은 안이 화면에 나갈 수 있는가? 걸린 안만 다시 요청하는가?
  - 추가 질문 선택지가 `TravelerTraits` 밖의 키·값으로 새 조건을 만들 수 있는가?
  - LLM 실패(시간 초과·형식 오류·한도) 때 규칙 일정 1안으로 떨어지는가? 가짜 LLM 테스트로 확인되는가?
- **'모름'은 숨기지 않고 확인할 방법을 준다.** access 값이 `가능 | 부분가능 | 불가 | 모름` 밖으로 나가는가? 빈칸을 '모름' 대신 지어낸 값으로 채우는가?
  '모름'에 질문(`ask`), 부분가능에 메모, 장소에 전화번호가 있는가? 등급(ai/human)이 화면에 표시되는가?
- **카카오 길찾기 결과 저장 금지.** 이동시간·시각·경로를 DB·파일·공유 링크·장기 캐시에 남기는가? 공유 링크는 안 JSON(장소·순서·체류·이유)만인가?
- **키는 서버에서만.** `NEXT_PUBLIC_`이 카카오 JS 키 말고 붙는가? 클라이언트 컴포넌트에서 REST·Gemini·Supabase 서비스 키를 쓰는가?
- **개인정보 없음.** 이름·연락처·IP를 받거나 저장하거나 Gemini로 보내는가? 자유 입력이 있으면 안내 문구와 서버 쪽 연락처 패턴 제거가 있는가?
- **경로 표현.** "휠체어 안전 경로"처럼 읽히는 문구가 있는가? "일반 차량 경로"로 표기했는가?
- **여러 유형 선택 시 가장 엄격한 값**, **장애인 주차는 자가용 + 표지 차량일 때만**이 지켜지는가?

## 일반 검토 영역
1. 사용자 목표와 정책(유형별 조건, 일정 밀도, 당일~2박 3일)
2. 입력·출력·상태 전이(입력 4단계 → 엔진 → 결과 → 편집 → 공유)
3. 정상·실패·경계 조건(후보 0곳, 꼭 가고 싶은 곳이 불가, 동절기·명절 휴무, 12~14시 점심, 숙소 미정)
4. 외부 서비스 장애(카카오 한도·오류 → 직선거리 추정치, Gemini 실패 → 규칙 기반 기본 브리핑)
5. 호출 횟수(다중 목적지 날짜마다 ≤6회, 경로선 1회)
6. 접근성(본문 16px↑, 터치 44px↑, 상태는 색 + 기호 ✓ ! ✕ + 글자, rem 단위로 글씨 크게, 키보드 조작)
7. 기존 기능에 대한 영향(입력 store, conditions.ts, 장소 스키마)
8. 테스트 가능성(엔진 시나리오 10개 중 어느 것을 깨고 고치는가, E2E로 볼 흐름)

## 검토 방식
- 기존 코드·문서에 근거한 **사실**과 **추정**을 나눠 적는다. 근거는 `파일:줄`로.
- 문제마다 심각도: 차단 / 높음 / 보통 / 낮음.
- 미결정 정책은 Claude가 정하지 않고 선택지(2~3개)로 제시한다. `docs/handoff.md`의 열린 결정과 겹치면 그 항목을 가리킨다.
- 이미 기준 문서에서 정한 것은 다시 묻지 않는다.
- 완료 조건이 자동 테스트(vitest·Playwright)로 확인 가능한지 평가한다.
